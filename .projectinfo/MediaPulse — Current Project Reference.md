## Product

MediaPulse is a movie discovery experience that interviews a viewer about what they enjoy in films, builds a compact taste profile and cinematic personality, then returns five personalized movie recommendations. Gemini proposes interview questions and movie candidates; the application validates AI output; TMDB verifies candidate identity and supplies the movie facts and artwork. The product principle is: **Gemini proposes. TMDB verifies. MediaPulse decides.**

V1 is movie-only, has no login, database, user accounts, or social features, and keeps Gemini and TMDB credentials on the server. The experience has a cinematic theater visual identity, an adaptive interview, a moviegoer personality card, and interactive DVD case recommendation cards.

## User journey and routes

1. `/` presents the landing page and explains the three-step experience.
2. `/quiz` opens a theater-themed adaptive interview. Its first prompt is the required free-text favorite-movie question; subsequent turns are generated by Gemini.
3. The interview ends after a minimum of five answered questions and no later than ten. Completion provides a taste profile, confidence, and personality.
4. The browser immediately hands the completed profile to the recommendation endpoint. The results screen shows the personality while recommendations load, then presents five verified movie cards. Users can retry a failed recommendation request or retake the interview.
5. `/api/health` is a small service health response; `/api/interview` and `/api/recommendations` are the server-side product endpoints.

Interview state and results are held in browser memory; there is no persistence layer.

## Architecture map

- `app/`: App Router pages, global styles, metadata, and API routes.
- `components/landing/`: landing hero, how-it-works section, and CTA.
- `components/interview/`: theater interview shell, typed question controls, validation feedback, progress, and completion wrapper.
- `components/results/`: personality reveal, movie artwork fallback, and interactive movie cases.
- `components/ui/`: shared buttons, containers, status/error UI, progress, header, and spinner.
- `services/gemini/`: server-only Gemini client, adaptive interview policy/service, and recommendation candidate generation.
- `services/tmdb/`: TMDB request client, search, details mapping, and conservative candidate verification.
- `services/recommendations/orchestrator.ts`: candidate batching, de-duplication, TMDB verification, and final five-item contract.
- `schemas/`: Zod runtime contracts; `types/` infers TypeScript types from those contracts.
- `lib/`: environment validation, safe API clients, answer/limit rules, error types, logging, and one-shot recommendation handoff.
- `config/` and `constants/`: model defaults, interview bounds, taste dimensions, and input/output limits.
- `*.test.mjs`: Node test suites for API routes, schemas, client adapters, prompts, TMDB verification, and recommendation orchestration.

## Request and validation boundaries

- Both product POST routes parse JSON, validate requests with Zod, and return a consistent `{ error: { code, message } }` shape for failures.
- Interview responses are discriminated as `continue` or `complete`. The server and client enforce the 5–10 question bounds; duplicate question IDs are rejected in the browser flow.
- Gemini structured output is projected from Zod JSON Schema into the provider's supported schema shape and then validated again against the full application schema.
- The Gemini client is server-only, uses `GEMINI_API_KEY`, classifies provider failures, redacts key-like details, and retries only transient failures with a bounded retry count.
- Recommendation generation requests 7–8 candidates, verifies them against TMDB, de-duplicates titles and TMDB IDs, and allows up to two batches to obtain five verified films. Uncertain title/year matches are rejected.
- `TMDB_API_KEY` is read on the server. Movie artwork is sourced from `image.tmdb.org`; the Next image configuration allows that host, while the component currently requests images without Next optimization.
- The interview system prompt source lives in this folder and is copied into `services/gemini/interview-prompt.ts`; that source file explicitly requires them to stay synchronized. Runtime guidance also clarifies that conceptual prompt dimensions must map to the schema's supported enum.
